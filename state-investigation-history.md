# Earlier pkg/state experiments

These are the observations retained through the [October 28 work map update](https://github.com/tamird/gvisor/commit/5e8f6c9be9623858dff54765f21d1e68efabb5a2). The [live investigation](https://tamird.github.io/gvisor/?view=investigations#investigation%3Astate-reflection-design) has the current findings, measurements and evidence links.

The second redesign (9f7e1bf5d2) waits for each value’s own conversions and hooks before copying it. Stock restored two map keys as a single zero key. A conversion saw 0 rather than 1 in a slice element, even though the slice retained the correct shared storage. Both regressions passed on the redesign, as did the full normal and race suites (21,642 passes, 174 skips) and the three state analyzer targets. Across 12 matched Linux AMD64 pairs, decoding plain structs with no hooks in adopt_uncaptured took 540.8 → 582.6 µs/op (+7.74%, p=.017) and one additional allocation per operation. The redesign remains under investigation; package timings do not measure checkpoint restore.

On the same 60-byte stream, a hand-written loader registered AfterLoad before converting a value read through a pointer. Master restored the value and observed 7 in the hook; the first proposed fix restored 7 but the hook observed 0. The earlier 0a10d127a2 change queued each struct’s AfterLoad hooks after its field conversions. Nested structs keep their own ordering before map insertion and copying values into interfaces. The full normal and race suites at 0e3067deeb reported 21,638 passes and 174 existing skips (87 per mode), with no failures or missing cases. All nine hook regressions passed in both modes. The standalone review commit 0a10d127a2 has exactly the same Git tree. Across 12 samples per arm, map decoding measured 360.6 → 357.7 μs/op (p=.799) and graph loading 647.6 → 661.3 ms/op (p=.887). Neither timing difference was significant. Map allocations rose from 1,854 to 1,855 per operation; graph allocations rose 0.010%. The parent failed to collect the report, but the original native XML and all 48 benchmark rows were recovered.

The byte-reader prototype can lose an I/O error on an ordinary bufio.Reader. A real state.Save produced the same 17-byte frame on the immediate parent and prototype. After its 10-byte header, the source returned a one-shot error, followed by the seven valid body bytes. On parent 2e84f83ca0, state.Load returned that error before reading the body. On prototype 6f252e393a, it read the body and returned 20261028 with no error. Both revisions restored 20261028 on the normal buffered control and propagated the same error through a plain reader. The prototype’s fresh test failed only this assertion. This tests error propagation, not an authenticated frame or a Sentry restore.

A handwritten StateSave that saves the same child in two slots restored one shared pointer on the parent (79 bytes) and two distinct pointers on the encode-dedup experiment (83 bytes). Both pointers held 73. Saving two distinct children with equal values restored distinct pointers and used 83 bytes on both revisions. No production saver passing the same nonzero-sized field address to two direct slots was found on this base. This isolates a compatibility question for custom savers; it does not measure checkpoint performance.

Formatting the finalized state statistics lazily, once per log message, avoids the eager table rendering when no output consumes it. In ten balanced pairs on one pinned AMD64 CPU, zero-output Save formatting fell from a median 353.584 microseconds and 2,541 allocations to 0.190 microseconds and four allocations; Load fell from 399.525 microseconds and 2,525 allocations to 0.235 microseconds and four allocations. Each enabled one- or two-output message rendered exactly once, preserving the same 521-row tables. Enabled-output timing differences were inconclusive (exploratory paired sign p=.344 to 1.000); this is not a claim of no overhead.

The 120 samples reuse one genuine finalized kernel Save/Load Stats input. Encoding happened outside sampling and sink writes were in memory. This measures formatting CPU/allocation cost, not physical logging, checkpoint I/O, actual restore or whole startup. The separate naive deferred-pointer control rendered twice with two outputs; the per-message memoized helper removes that duplication. The source-bound prototype and independently reviewed retained result passed; no new contributor decision or competing state rewrite is proposed. Parth retains rewrite ownership.

Reusing an already registered slice backing array showed no demonstrated Load improvement on the real Nginx checkpoint. Twelve alternating pairs measured wall time at 14.497 to 13.986 ms (p=.160) and CPU at 14.484 to 13.976 ms (p=.143), with 94,126 allocations in both arms. The earlier 14.08% shared-backing microbenchmark improvement does not establish a checkpoint benefit. An untimed pass counted 23 prior-root and 91 first registrations; a prior root may have been registered by a pointer or enclosing object. This comparison reads one 309,276-byte state file and excludes page I/O, application restore and startup. Parth retains ownership of the rewrite.
